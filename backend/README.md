# Sinavigator backend

The Python service exposes the computed data bundle and study metadata to the
Next.js frontend. It validates the bundle against the TypeScript contract before
serving it; a missing or malformed bundle is reported explicitly, not replaced
with synthetic scientific output.

## Current project data flow

1. The workspace loads its shared `Bundle` through the same-origin
   `/api/bundle` Next.js route.
2. That route proxies to this service at `http://127.0.0.1:8000/api/v1/bundle`.
   Set `SINAVIGATOR_BACKEND_URL` on the Next.js server if the backend listens
   elsewhere.
3. This service reads `frontend/public/data/bundle.json`, validates it, and
   returns the same JSON shape consumed by `frontend/src/lib/data/types.ts`.
   `SINAVIGATOR_BUNDLE_PATH` can point at a different generated file.
4. If the Python API is unavailable, the frontend can still use the existing
   static bundle. If neither source is usable, it displays the explicitly
   labeled synthetic fixture.

The bundle is currently generated by
`frontend/tools/terrain/build-apollo-comparison.mjs`, because that existing
pipeline reads the local LROC GLB meshes and checks remote JPL Horizons output.
The backend deliberately does not claim to compute SPICE ephemerides or DEM
horizons until those calculations are independently implemented and validated.

## Run

From the repository root:

```bash
python -m venv backend/.venv
backend/.venv/Scripts/python -m pip install -r backend/requirements.txt
backend/.venv/Scripts/python -m backend.run
```

On Linux, use `backend/.venv/bin/python` in place of
`backend/.venv/Scripts/python`. To run directly from `backend/`, activate its
virtual environment and use `python run.py`.

The API listens on `0.0.0.0:8000`; Uvicorn trusts forwarded headers only from
Nginx Proxy Manager at `192.168.111.140`.

## Endpoints

- `GET /health` — process liveness.
- `GET /ready` — confirms a valid bundle is available.
- `GET /api/v1/bundle` — validated bundle used by the workspace.
- `GET /api/v1/sites` — site catalog and provenance.
- `GET /api/v1/config` — scenario and visibility assumptions.

## Tests

```bash
backend/.venv/Scripts/python -m unittest discover -s backend/tests
```

The tests validate the current generated Apollo 15/Apollo 17 bundle and verify
that malformed or missing data produces explicit errors.
